# Design notes for the UI prototype

`prototype.tsx` (generated by Gemini) is the approved **visual** reference: layout, density, colours, typography and component styling. It is **not** a behaviour reference. Where it disagrees with `docs/nestbox-spec.md`, the spec wins.

## Take from the prototype

- Overall layout: title bar, left sidebar (filter, pinned section, all projects, "Add project" at the bottom), project header with metadata row and action buttons, icon tabs, bottom status bar.
- Card, table, badge, button and modal styling; status badges with tinted background + border.
- Log viewer look: timestamp, level badge, context, message, muted details on the right.
- Command palette, toast and confirm-dialog styling.
- Design tokens: bg `#0D1117`, card `#161B22`, surface `#21262D`, hover `#2A303C`, border `#30363D`, text `#C9D1D9` / `#8B949E` / `#484F58`, accent `#7C8CFF` (hover `#697AFA`), status green `#3FB950`, amber `#D29922`, red `#F85149`, grey `#8B949E`. Put them in the Tailwind theme; no hard-coded hex in components.

## Do not copy (prototype deviates from the spec)

| Prototype | Build instead |
| --- | --- |
| macOS traffic-light buttons, `⌘K` hint | Windows-first: native/overlay title bar controls (`titleBarOverlay`), show `Ctrl+K` on Windows, `⌘K` on macOS |
| "Daemon Connected", "Nestbox Daemon" log line | No daemon. The Electron main process does the work; drop daemon wording |
| System CPU/RAM in status bar; per-script CPU/RAM | Not in v1. Status bar: running processes, ports in use, palette hint |
| Single shared log pane mixing all projects | Per-script log panes for the selected project, split view for two panes; logs are per process |
| "ANSI Plain Console" is actually formatted rows | Plain mode renders real ANSI output; JSON mode parses structured lines (pino/NestJS) with level/context/requestId filters |
| Script list has only play/stop | Start, stop, restart; run groups; amber "starting" state; crash state with error |
| Env: one "Reveal Masked Values" toggle for all | Reveal one value at a time; copy without revealing; never reveal all at once |
| Env: only `.env` vs `.env.example` | Matrix of every `.env*` file (keys as rows, files as columns) |
| Ports: "Free All Inactive Ports" | Not in spec; remove |
| Ports: confirm dialog for every kill | Confirm only for processes Nestbox did not start |
| Claude tab: "Proposed Runtime Patch from Claude" editing `package.json` | Nestbox's own context generator: a diff of the `<!-- nestbox:start/end -->` "Project runtime" block in `CLAUDE.md`, with Apply |
| Claude tab: "Sync MCP Context" | Read-only lists of slash commands, subagents and `.mcp.json` servers; actions Open in Claude Code, Continue last session, Quick prompt; gitignore warning |
| Purple (`purple-400`) for Claude elements | No second accent; use `#7C8CFF` or neutral text |
| Glowing status dots, backdrop blur | Flat: plain dots, solid overlays |
| "Kill All" in the project header | Keep, but label it "Stop all" and stop only Nestbox-started processes |
| Static server toggles: SPA, CORS, HTTPS | Also no-cache and simulated latency; default port must not clash with the dev server |
| Fake versions (v1.4.0, Claude CLI v0.2.14), `/Users/...` paths | Real values from the app; Windows-style paths in Windows builds |

## Brand assets

Final assets live in `resources/brand/` (the source of truth; `docs/design/nestbox-logo.png` is only the original concept image and is not used in the app).

| File | Use |
| --- | --- |
| `svg/nestbox-mark.svg` | The mark (graphite body, `#7C8CFF` hole, perch cut out). In-app logo in the title bar and sidebar; recolour via `fill`, never redraw it |
| `svg/nestbox-app-icon.svg` | Source for the app icon |
| `svg/nestbox-lockup.svg` | Mark + wordmark for README and About screen. The wordmark is live text: convert to outlines before using it anywhere public |
| `svg/nestbox-tray-16.svg`, `svg/nestbox-tray-32.svg` | Sources for the tray PNGs; body is `currentColor`, hole is `var(--hole)` |
| `png/nestbox.ico` | Windows app icon for electron-builder (`build.win.icon`) and the `BrowserWindow` icon |
| `png/app-icon-{16..512}.png` | App icon sizes (512 for Linux/macOS builds later, smaller ones for in-app use) |
| `png/tray/tray-{theme}-{state}-{16,32}.png` | Tray icons: `theme` is `dark-taskbar` (white body) or `light-taskbar` (graphite body); `state` is `running`, `starting`, `crashed`, `idle` |

**Tray wiring**

- Build the tray image with `nativeImage.createFromPath(...16.png)` and add the 32 px file as the 2x representation (`addRepresentation({ scaleFactor: 2, ... })`) so it stays sharp on high-DPI screens.
- Tray state is the worst state across all tracked processes: any crashed → `crashed`, else any starting → `starting`, else any running → `running`, else `idle`.
- Windows: the taskbar theme can differ from the app theme. Default to `dark-taskbar` icons (Windows' default), and add a setting `trayIconTheme: 'auto' | 'dark-taskbar' | 'light-taskbar'`; `auto` uses `nativeTheme.shouldUseDarkColors`.
- macOS (later): don't use template images, because they drop the coloured hole; use the same PNGs and pick the theme from `nativeTheme`.
- Keep a single asset loader in `src/main/` that resolves these paths for both dev and the packaged app (`process.resourcesPath`); add `resources/brand` to electron-builder's `extraResources`.

## Code

The prototype is one untyped 1,190-line file with hard-coded colours (its `TOKENS` object is unused). Rebuild it with the spec's structure: shadcn/ui components, tokens in the Tailwind theme, one component per tool panel, typed props, no mock data in production code.
